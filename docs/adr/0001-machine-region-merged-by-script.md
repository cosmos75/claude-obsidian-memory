# 筆記的人類區由腳本保護，不交給 LLM

`stars-to-obsidian` 這條管道除了寫檔以外全是自然語言步驟，唯獨檔案的合併與寫入交給一支腳本：LLM 只生成機器區內容並落到暫存檔，再由腳本讀出舊筆記、切出 `## 我的筆記` 以下的人類區、重組後寫回。這麼做是因為「人類區永不被覆寫」是一條資料不可遺失的不變量，而 `--refresh` 是整篇覆寫的破壞性操作——把這種不變量交給提示詞裡的一句話，失敗時是靜默的，使用者往往在版本歷史都滾掉之後才發現。讓人類區的內容根本不經過 LLM 的手，這件事就從「大概率正確」變成「結構上不可能出錯」。

## Considered Options

- **純提示詞 + 事前備份整個資料夾**：零程式碼，但風險依舊存在只是可回復，且要求使用者先察覺出事；備份資料夾還會被 Obsidian 當成筆記索引。
- **接受風險暫不處理**：當下 `--refresh` 執行次數為 0、手寫心得為 0 篇，風險為零。但風險會隨著標註越多而變大，屆時要補救的成本也更高。

## Consequences

`stars-to-obsidian` 不再是一條純自然語言的管道，指令中多出「寫暫存檔 → 呼叫腳本」這一步。這是刻意的不對稱：其餘分析、分類、產生內容的工作仍然全部由 LLM 負責，腳本的職責僅限於安全地寫檔。
