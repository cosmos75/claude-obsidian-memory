# Domain docs

工程類 skill 在探索這個 codebase 時，該怎麼使用這個 repo 的領域文件。

**這是單一 context 的 repo**：根目錄一份 `CONTEXT.md`，根目錄一個 `docs/adr/`。沒有 `CONTEXT-MAP.md`，不需要為了找 context 而先讀導覽檔。

## 動手之前先讀

- **`CONTEXT.md`**（根目錄）——這個專案的領域詞彙表。
- **`docs/adr/`**——讀跟你要動的區域相關的那幾份 ADR。

這些檔案若不存在，**安靜地繼續做事**。不要特地指出它們不在、也不要主動建議先建立它們。它們由 `/grill-with-docs` 在術語或決策真的被釐清時才逐步產生。

## 用詞彙表裡的字

當你的產出提到某個領域概念（issue 標題、重構提案、假設、測試名稱），就用 `CONTEXT.md` 裡定義的那個詞，不要漂移到它明確標示要避開的同義詞。

如果你需要的概念還不在詞彙表裡，那是個訊號——要嘛你正在發明這個專案不使用的語言（請重新考慮），要嘛真的有缺口（記下來，留給 `/grill-with-docs`）。

## 跟 ADR 衝突要明講

如果你的產出牴觸了某份既有 ADR，把它攤開來講，不要默默蓋過去：

> _這牴觸了 ADR-0002（管道產物靠來源標記辨識），但值得重新討論，因為……_
